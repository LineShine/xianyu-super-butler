# 一次性迁移

仅支持已初始化的原生方式五来源。正常启动不读取来源目录，也不读取 Compose 配置或连接容器。

1. 先停止其他会向来源库写入的脚本或旧应用。`migrate --dry-run` 核对来源实例身份、表映射和行数，不写数据。
2. 正式 `migrate` 准备依赖并检查目标为空，然后调用来源统一入口停止其服务。若来源端口仍在监听则报错停止。
3. 在目标目录外的 `.yutaixian-backups/migration-时间-随机标识/` 保存原生数据库、上传资源、浏览器资料和配置快照，并记录文件 SHA-256。
4. 使用快照的第二份副本，通过私有 Unix socket 启动临时 MySQL、Redis。原目录和第一份快照不启动、不修改。
5. 根据 `config/migration-map.json` 创建独立结构，以参数化 INSERT 导入。保留主键、密码哈希、订单状态和卡券正文。未知表或字段会阻止迁移，避免静默丢失。商业字段与表按清单排除。
6. 逐表比较行数和有序多重集摘要，检查用户与卡券关联；复制资源并验证文件摘要。Redis 使用 DUMP/RESTORE 保留类型和剩余有效期，排除锁、认证会话与临时运行键。
7. 重新生成数据库、Redis、JWT、内部服务令牌；替换明确的产品配置项。校验通过后停止临时进程，再允许 `start` 启动业务服务。

状态保存在 `yutaixian_data/local_dev/data-migration.json`。失败后再次执行同一来源的迁移命令，将从已校验快照重新导入；不会使用正在变化的原库覆盖快照。已完成的迁移命令再次执行只报告完成状态，不重复导入。

详细报告在 `yutaixian_data/local_dev/migration-report.json`，包含每张表的保留/排除结果、字段差异、行数、摘要、关联检查、文件校验、Redis 转换与排除记录。报告及快照属于私有运行资料，不纳入 Git。

迁移不合并旧鱼太咸单体后端的数据。旧仓库、未提交修改、SQLite 数据、浏览器资料与配置由切换流程整体保存在目录外，原项目方式三保持不变。不会在失败后自动恢复旧应用。

历史数据库备份文件保持原始内容，以 `ytx_archive_<记录ID>.sql.gz` 归档，并迁移下载记录的文件名和路径。它们属于旧结构历史存档，不能直接导入新业务库；当前实例生成的新备份使用新的数据库和表名。
