# 商品口令生成

商品管理在「AI提示词」之后提供「口令生成」开关，所有商品默认关闭，按账号和商品独立保存。

开启后支持卖家手动生成和买家自助验单领取。卖家在鱼太咸 Web 聊天或闲鱼 App 的商品单聊中发送完整的 `生成口令` 或 `口令生成`。买家先收到卖家的四字指令，再收到服务器生成的六位口令。卖家指令中的空格、换行、标点、引用以及自动消息回传均不触发。

## 买家自助领取

买家的普通文本包含“口令”且能确认当前商品时，回复：

> 请提供纯数字的订单编号，将自动发放口令（不要发送多余内容，避免自动发放失败）

从本轮开始等待五分钟，重复询问不重置时间。仅接受 1–64 位 ASCII 数字订单号，不截取、不修剪空白。格式不对每轮只提醒一次“请仅发送数字订单号，不要附加其他内容”。收到订单号后发送“已收到，正在自动处理ing...”，再使用当前卖家的 Cookie 查询闲鱼实时订单详情，校验订单编号、卖家、买家、商品、已付款和未退款。

待发货、已发货和已完成的有效订单均可领取。退款中、已退款、部分退款、未付款、关闭以及接口返回关键字段不足或矛盾时均停止。不会把本地订单缓存、请求参数、缺少退款记录或未知状态码当作放行证据；不触发确认发货、退款操作或后台循环重试。

订单详情实际使用 `seller: true` 表示当前登录者为卖家，配合已校验的登录账号身份和 `peerUserId` 确认买卖双方；也兼容明确返回卖家 ID 的结构。再按完整订单号查询卖家已售接口，交叉核对订单、买家和商品，并同时检查 `commonData.inRefund` 与 `priceVO.refundFee`，防止把已结束的部分退款当作无退款。两次只读查询合计最多 20 秒，缺少依据时停止，不自动重试。

验单失败回复“机器人回复：订单异常，{业务原因}（五分钟内可重新发送订单号）”，允许在原来的剩余等待时间内纠正。成功时依次发送“口令生成”和六位口令，结束本轮。生成通过内部可信入口执行；可见的“口令生成”消息及其回传不会再次触发脚本。

每笔订单（按卖家账号隔离）每天最多自动领取三次，以最终发送当天的北京时间日期统计；成功后冷却五分钟，跨零点不清除冷却。明确失败释放额度，最终口令发送无回执、发送中断或网络结果不明保留一次占用，不自动补发。提示消息失败或结果未知会终止后续步骤，且不占最终口令额度。超过上限回复“该订单今日已领取超过限制”，冷却中告知剩余秒数。卖家手动指令不受自助额度限制。

等待期间买家的消息由本轮流程处理，避免 AI、关键词及默认回复插话；付款等系统事件保留原有处理。超时静默结束，服务重启保留未过期等待；正在发放的任务不重放，失效占用在下一次消息或同订单领取时清理，可能已经发出的口令保留额度。商品关闭、重新开启、账号禁用或会话归属变化会使旧流程失效。

使用独立的 `ytx_code_self_service_sessions` 与 `ytx_code_self_service_attempts` 表保存会话、源消息去重、步骤和每日额度，启动时幂等创建。清理普通回复日志不会重置领取额度。表创建失败会中止数据库初始化，避免无持久化记录时发放。回复日志中的“口令生成”展示人工／买家自助来源、订单、阶段、当日额度和异常原因。

## 共用执行规则

仅处理本次开启之后、最近五分钟内且具有有效原始时间的指令。商品或买家无法唯一确认时停止，原因记录在「回复日志」的「口令生成」规则中。功能不依赖 AI 开关，人工发出消息仍保留原来的 AI 暂停行为。

服务器使用服务自身的 Python 3 解释器执行 `common/custom_func/generate_code.py` 的绝对路径，脚本算法保持不变。执行不经过 shell，不接收聊天文本参数，最多运行五秒；只接受成功退出且输出六位大小写字母或数字的结果。脚本按原规则可能在同一秒产生相同口令。

同一会话串行处理，以账号、会话、源消息 ID（缺失时包含原始时间的指纹）在现有回复日志中持久化占用。重复推送和重启后的重复消息不会再次执行；卖家发送新的指令可以再次生成。

发送前重新检查商品开关、开启时间和账号启用状态。闲鱼明确确认才记录「发送成功」；拦截记录失败；无回执或处理中断记录结果未知，不自动重试或补发。遇到未知状态请先检查聊天记录，再决定是否发送新指令。脚本报错不会向买家发送错误文本。

配置接口：`PUT /api/v1/items/{cookie_id}/{item_id}/code-generation`，请求 `{"enabled": true}` 或 `{"enabled": false}`，校验账号和商品归属。配置存入商品 metadata 的 `code_generation_enabled` 和 `code_generation_enabled_at`（Unix 毫秒），商品同步保留它们。幂等开启不刷新时间，关闭后重新开启会生成新时间。
