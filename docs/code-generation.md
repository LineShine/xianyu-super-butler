# 商品口令生成

商品管理在「AI提示词」之后提供「口令生成」开关，所有商品默认关闭，按账号和商品独立保存。

开启后支持卖家手动生成和买家自助验单领取。卖家在鱼太咸 Web 聊天或闲鱼 App 的商品单聊中发送完整的 `生成口令` 或 `口令生成`。买家先收到卖家的四字指令，再收到服务器生成的六位口令。卖家指令中的空格、换行、标点、引用以及自动消息回传均不触发。

## 买家自助领取

买家的普通文本包含“口令”且能确认当前商品时，回复：

> 请提供订单编号，将自动发放口令（纯数字，不要发送多余内容，避免自动发放失败）

从本轮开始等待五分钟，重复询问不重置时间。买家订单号允许首尾空白（包括空格、换行、制表符及全角空格），去除后必须完整匹配 1–64 位 ASCII 数字；不截取混合文字中的数字，不删除数字中间的空白，不转换全角数字。验单和领取额度使用去除首尾空白后的订单号，日志与消息去重保留原始内容；卖家四字指令仍严格匹配。等待订单号期间，每条格式不符的新消息均回复“请仅发送数字订单编号，不要附加其他内容”（FORMAT_HINT），包括再次发送“口令”、数字夹杂文字、纯空白及图片；同一条消息的重复推送不会重复回复。收到订单号后发送“已收到，正在自动处理ing...”，再使用当前卖家的 Cookie 查询闲鱼实时订单详情，校验订单编号、卖家、买家、商品、已付款和未退款。

待发货、已发货和已完成的有效订单均可领取。退款中、已退款、部分退款、未付款、关闭以及接口返回关键字段不足或矛盾时均停止。不会把本地订单缓存、请求参数、缺少退款记录或未知状态码当作放行证据；不触发确认发货、退款操作或后台循环重试。

订单详情实际使用 `seller: true` 表示当前登录者为卖家，配合已校验的登录账号身份和 `peerUserId` 确认买卖双方；也兼容明确返回卖家 ID 的结构。再按完整订单号查询卖家已售接口，交叉核对订单、买家和商品，并同时检查 `commonData.inRefund` 与 `priceVO.refundFee`，防止把已结束的部分退款当作无退款。两次只读查询合计最多 20 秒，缺少依据时停止，不自动重试。

验单失败回复“机器人回复：订单异常，{业务原因}（五分钟内可重新发送订单号）”，允许在原来的剩余等待时间内纠正。成功时依次发送“口令生成”和六位口令，结束本轮。生成通过内部可信入口执行；可见的“口令生成”消息及其回传不会再次触发脚本。自动回传识别窗口为 5 秒（内存追踪和持久化记录一致）；窗口内人工发送同文指令仍可能被跳过。

每笔订单（按卖家账号隔离）每天最多自动领取三次，以最终发送时本机系统时间对应的北京时间日期统计；成功后冷却三分钟，跨零点不清除冷却。明确失败释放额度，最终口令发送无回执、发送中断或网络结果不明保留一次占用，不自动补发。提示消息失败或结果未知会终止后续步骤，且不占最终口令额度。超过上限回复“该订单今日已领取超过限制”，冷却中告知剩余秒数。卖家手动指令不受自助额度限制。

等待期间买家的消息由本轮流程处理，避免 AI、关键词及默认回复插话；付款等系统事件保留原有处理。超时静默结束，服务重启保留未过期等待；正在发放的任务不重放，失效占用在下一次消息或同订单领取时清理，可能已经发出的口令保留额度。商品关闭、重新开启、账号禁用或会话归属变化会使旧流程失效。

使用独立的 `ytx_code_self_service_sessions` 与 `ytx_code_self_service_attempts` 表保存会话、源消息去重、步骤和每日额度，启动时幂等创建。清理普通回复日志不会重置领取额度。表创建失败会中止数据库初始化，避免无持久化记录时发放。回复日志中的“口令生成”展示人工／买家自助来源、订单、阶段、当日额度和异常原因。

## 共用执行规则

口令流程以本机接收消息的时间为准，不再将闲鱼原始消息时间与本机系统时间或商品开启时间比较。原始时间仍须有效，用于日志、去重和自动回传识别；商品开启时间作为配置版本，执行中关闭或重新开启仍会停止原任务。消息接收后的五分钟有效期、等待窗口和冷却使用单调时钟计时，因此运行中调快或调慢系统时间不会误判新消息或打断正在处理的任务。服务重启后使用持久化状态恢复；旧时间坐标下超过正常期限的等待、占用和冷却会失效，避免回拨后长期卡住。商品或买家无法唯一确认时停止，原因记录在「回复日志」的「口令生成」规则中。功能不依赖 AI 开关，人工发出消息仍保留原来的 AI 暂停行为。

服务器使用服务自身的 Python 3 解释器执行 `common/custom_func/generate_code.py` 的绝对路径，脚本算法保持不变。执行不经过 shell，不接收聊天文本参数，最多运行五秒；只接受成功退出且输出六位大小写字母或数字的结果。脚本按原规则可能在同一秒产生相同口令。

同一会话串行处理，以账号、会话、源消息 ID（缺失时包含原始时间的指纹）在现有回复日志中持久化占用。重复推送和重启后的重复消息不会再次执行；卖家发送新的指令可以再次生成。

发送前重新检查商品开关、开启时间和账号启用状态。闲鱼明确确认才记录「发送成功」；拦截记录失败；无回执或处理中断记录结果未知，不自动重试或补发。遇到未知状态请先检查聊天记录，再决定是否发送新指令。脚本报错不会向买家发送错误文本。

配置接口：`PUT /api/v1/items/{cookie_id}/{item_id}/code-generation`，请求 `{"enabled": true}` 或 `{"enabled": false}`，校验账号和商品归属。配置存入商品 metadata 的 `code_generation_enabled` 和 `code_generation_enabled_at`（Unix 毫秒），商品同步保留它们。幂等开启不刷新时间，关闭后重新开启会生成新时间。

## 消息接收健康检查

托管连接每 30 秒只读检查最近 20 个会话，每轮最多核对 5 个变化或待确认会话的最近 20 条聊天记录。首次成功查询建立平台消息时间基线，不处理历史消息。只对基线之后的新买家正文核对消息 ID；多次查询确认且至少 60 秒仍无实时接收记录，才启动恢复。无人聊天、历史消息、卖家自动发送、查询失败或流控均不会单独触发离线判定。检测不补发历史口令或发货消息。

异常先刷新 Token 并自动重连，最多 2 次。每次连接恢复后重新建立检测基线，等待新的买家消息验证；没有新消息时显示“重连验证中”，不判失败。重连后再次确认新消息漏收，才继续下一次；连接恢复失败也计一次。两次尝试后仍异常，账号显示离线及“消息接收异常，请重新扫码登录”，不计入仪表盘在线账号；账号保持启用，定时补发货继续可用。重新扫码创建新连接后重新检测，或收到新的买家正文后解除异常。

重连结果、重试耗尽和接收恢复写入风控日志（事件类型 message_sync），按账号归属隔离；此事件表示消息通道异常，并不代表平台确认了风控。健康状态和检测基线随进程重启重新建立；本轮重连计数在同一账号实例内保留。账号页面每 30 秒静默更新状态，打开编辑弹窗时暂停页面刷新。
